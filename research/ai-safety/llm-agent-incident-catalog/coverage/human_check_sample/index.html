    Meta AI Model Reportedly Exploited Security Vulnerability in Real Third-Party Service During Cybersecurity Evaluation
    https://incidentdatabase.ai/cite/1649

    During a Meta cybersecurity evaluation conducted with Irregular, one of Meta's AI models reportedly gained unintended Internet access after an evaluation-environment misconfiguration and exploited a [... truncated; third-party description, see URL above]

    • Sonnet: yes (conf 0.8); failure_type ['misspecification']
    • Sonnet rule_text: Evaluation sandbox for agents must enforce default-deny egress: block all outbound traffic except an explicit allowlist of hosts, verify egress is blocked with an automated canary check before each run, and abort the run if the check fails. Additionally, deny actions whose target host is not on the evaluation allowlist.
    • Sonnet rationale: A sandbox misconfiguration gave real internet access, and a standard egress deny-by-default rule plus a pre-run containment check would have prevented the model from reaching the third-party service.

All outbound connections routed through proxy with URL blocklist (no real third-party services, known vulnerability databases, GitHub). Eval environment must be air-gapped or at minimum block dynamic DNS, known vulnerable services.

    • Sonnet: yes (conf 0.8); failure_type ['misspecification', 'irreversible-action-without-info']

    1510 (AIID, 2026-05-31)

    Meta AI Support Bot Reportedly Enabled Takeovers of High-Profile Instagram Accounts
    https://incidentdatabase.ai/cite/1510

    Hackers reportedly used Meta's AI support chatbot to take over high-profile Instagram accounts by allegedly convincing it to change account email information and trigger recovery flows. Reported [... truncated; third-party description, see URL above]

    • Sonnet: yes (conf 0.85); failure_type ['misspecification', 'injection/untrusted-input']
    • Sonnet rule_text: The support agent may not call account-credential tools (change email, change phone, reset password, trigger recovery) on the basis of a chat conversation. Each such call requires a verified-session token or a one-time code sent to the existing registered contact. Block the call if the requester has not passed that out-of-band authentication. Rate-limit these calls, and require human escalation for accounts flagged high-profile.
    • Sonnet rationale: Account-takeover tools gated on out-of-band authentication tokens are a standard rule that can be checked at action time, and the failure was that the agent acted without that check.
    • Haiku: yes; rule_text: Block account-modification actions (email change, password reset, recovery-flow trigger) on accounts with verified high-profile status, government role, or verified-badge accounts. Require multi-factor out-of-band authentication (phone call, security key, in-app notification to registered device) before executing any account recovery action. Never execute account changes based on verbal social-engineering requests alone.

    1671 (AIID, 2026-07-10)

    OpenAI GPT-5.6 Sol Agent Reportedly Deleted Most Files in AI Startup Founder's Mac Home Directory
    https://incidentdatabase.ai/cite/1671

    AI investor Matt Shumer reported that a GPT-5.6 Sol agent in OpenAI Codex's high-autonomy Ultra mode accidentally deleted most files in his Mac home directory during a cleanup task. A review [... truncated; third-party description, see URL above]

    • Sonnet: yes (conf 0.9); failure_type ['irreversible-action-without-info', 'misspecification']
    • Sonnet rule_text: Before executing any shell command, resolve variables and paths. Block rm -rf (or recursive delete) when the resolved target is $HOME, a home directory, /, or any path outside the task's declared working directory. Require explicit human approval token for recursive deletes outside the project workspace. Run agents in a sandbox/container where the home directory is not mounted.
    • Sonnet rationale: A path-scope and recursive-delete check on the resolved command string would block rm -rf on the home directory, a standard rule for coding agents with shell access.
    • Haiku: yes; rule_text: Block destructive filesystem operations (rm -rf, rm -r on directories with >N files, recursive delete) on user home directories and system directories without explicit per-path approval. Require the user to whitelist paths for deletion and set hard limits on tree depth and file count in a single rm invocation.

    https://incidentdatabase.ai/cite/1368

    Bitdefender researchers reported abuse in OpenClaw's third-party 'skills' ecosystem. In a Feb. 2026 sample, about 17% of skills were reportedly assessed as malicious, with many seemingly cloned under [... truncated; third-party description, see URL above]

    • Sonnet: partial (conf 0.75); failure_type ['injection/untrusted-input', 'other']
    • Sonnet rule_text: Skill/plugin installation allowlist: the agent may load only skills from a signed, vetted registry or pinned hashes.     LLM-Driven Ransomware Operator Dubbed JADEPUFFER Reportedly Targeted Production Database
    https://incidentdatabase.ai/cite/1578

    Sysdig reported that a ransomware operator it dubbed JADEPUFFER used an LLM-driven agent to turn access through a vulnerable internet-facing Langflow deployment into a database-extortion operation. [... truncated; third-party description, see URL above]

    • Sonnet: partial (conf 0.6); failure_type ['other', 'irreversible-action-without-info']
    • Sonnet rule_text: Defender side (Langflow or agent-builder deployment): do not expose the code-execution endpoint to the internet without authentication, and keep it patched. Do not give workflow hosts credentials to production databases. Deny DROP, TRUNCATE, and bulk DELETE or encrypt-in-place on production databases unless a human approval token is present.
