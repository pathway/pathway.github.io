    Sources checked

    Compiled 2026-11-20. This records every sweep made for the catalog, which leads were verified, and which were dropped. Verification rule: every catalog row was confirmed against at least one primary or near-primary source opened in the browser (vendor postmortem, operator write-up, CVE record, peer-reviewed paper, or reputable news naming its source).

    Existing incident databases

    Each database below was opened and inspected. "Agent-specific" means the database is built specifically around AI agents that take actions (not AI harms in general).

    Database URL Scope Agent tag/filter? ~LLM-agent entries Usable for our catalog?
    AI Incident Database (AIID) https://incidentdatabase.ai General real-world AI harms since 2018; 1,700+ incidents No dedicated agent tag, but entity pages act as filters: "LLM-integrated code assistants", "Claude Code", "Cursor", "Gemini CLI", "vibe coding platform" Dozens via those entity pages (code-assistant entity lists ~8-10; many 2026 destructive-agent incidents) Yes - primary aggregator used; each entry links source reports we re-opened
    OECD AI Incidents & Hazards Monitor (AIM) https://oecd.ai/en/incidents Media-driven monitor; ~19,243 incidents & hazards No "LLM agent" tag, but an autonomy-level filter (up to "human-out-of-the-loop") Not separable from the total Partly - good for cross-checking dates; no agent view
    AIAAIC Repository https://www.aiaaic.org/aiaaic-repository AI/algorithmic/automation incidents; 500+ entries No agent/agentic category; domain taxonomy only Few, scattered across domains Partly - background only
    MIT AI Risk Repository + AI Incident Tracker https://airisk.mit.edu/ 1,700+ risks from 65 frameworks; separate incident tracker classifying AIID incidents No agent-specific category Not separable Partly - taxonomy reference, not a direct source
    AI Vulnerability Database (AVID) https://avidml.org/database/ GPAI failure modes; 500+ records; scope explicitly names "developer tooling... and agents" Covers prompt injection; no single agent filter seen Several (prompt-injection, agent framework entries); latest records 2026-03-17 Partly - useful for CVE-class corroboration
    METR, Documented AI Agent Incidents https://metr.org/agent-incidents/ Agent-specific. Incidents where agents acted against the user's intention; 44 incidents, data through 2026-05-19, scored on overreach and deception Yes - the whole catalog is agent incidents 44 (18 METR evals, 24 public, 2 anonymous) Yes as corroboration; most sources are system cards / blogs we also used
    Agent Incident Registry (AIR), Enkrypt AI / Anaconda https://air.enkryptai.com (paper arXiv:2609.11030) Agent-specific. Source-linked catalog, 487-529 records 2022-2026, verbatim-quote rule, taxonomy of causal role / disclosure class / mechanism / outcome Yes - purpose-built for agent incidents ~487-529 (200 with realized harm) Yes - closest peer to this catalog; methodology mirrors ours
    Eon, Rogue AI Agent Tracker https://www.eon.io/rogue-ai-agent-tracker Agent-specific. Confirmed agent incidents causing production damage, data loss, agent-assisted attacks, eval escapes; ~77 incidents Yes ~77 (33 accidents, 18 agent-assisted attacks, 5 eval escapes) Yes as corroboration
    Vibe Graveyard https://vibegraveyard.ai/ Broad catalog of AI failures incl. vibe-coding disasters; 60+ stories Not agent-specific; mixes autonomous-vehicle, legal, chatbot failures ~15-20 coding-agent stories Partly - lead-finding only
    OWASP GenAI Security Project, Incident & Exploit Round-ups https://genai.owasp.org/2025/07/14/owasp-gen-ai-incident-exploit-round-up-q225/ ; https://genai.owasp.org/2025/03/06/owasp-gen-ai-incident-exploit-round-up-jan-feb-2025/ Quarterly GenAI incident lists; 2026 Top-10 weighted by 6,639 incidents No agentic tag on entries (Q2'25 list verified - none tagged agentic) Few true agent-action entries (most are jailbreaks, deepfakes, data leaks) Partly - EchoLeak and tool-poisoning entries reused
    Simon Willison, prompt-injection tag https://simonwillison.net/tags/prompt-injection/ Curated link blog; 163 posts 2022-2026 De facto agent/injection focus Dozens of product exploits Yes - lead index; linked to primaries we opened
    Embrace The Red (J. Rehberger) https://embracethered.com/blog/ Researcher disclosures against named products De facto agent focus ~50 product-specific exploit posts 2023-2026 Yes - many primary sources

    Is any existing database agent-specific? Yes - three are: METR's Documented AI Agent Incidents, the Agent Incident Registry (Enkrypt AI/Anaconda), and Eon's Rogue AI Agent Tracker. The large general databases (AIID, OECD AIM, AIAAIC, MIT) are not agent-specific; AIID is the most useful of these because its entity pages and 2026 coverage effectively surface agent incidents and link primary reports. The Agent Incident Registry (487-529 source-linked records) is the closest peer to this catalog and is the best external cross-check.

    Papers swept for an incident appendix

    • Shapira et al. 2026, "Agents of Chaos" (arXiv:2602.20021) - opened. No appendix of real-world deployed incidents. It is a lab red-team study (OpenClaw framework, Claude Opus 4.6 + Kimi K2.5, Fly.io VMs, Discord + ProtonMail, 20 researchers, 2 weeks) with 11 representative failure classes. Recorded as lab-only row L6.
    • AgentDojo (arXiv:2406.13352) - opened. Motivational only; a benchmark (97 tasks, 629 security tests), no catalog of real incidents.
    • Greshake et al. 2023 (arXiv:2302.12173) - opened. Seminal indirect-injection paper; demos against Bing Chat (GPT-4) and code-completion engines. Catalog row C01.
